# Дизайн и технические решения

## Визуальное направление

Сохранена основа существующего сайта: Minecraft / Blender, тёмная тема, оранжевые акценты, авторские рендеры и неформальный русский текст. Вместо множества одинаковых панелей — крупный первый экран, небольшая подборка работ, фотокарточка автора, интерактивный прайс и светлый блок отзывов. Наклонённая рамка и знак-куб связывают интерфейс с объёмной графикой.

Manrope используется для текста, Unbounded — для заголовков. Оба шрифта включены локально, содержат кириллицу и распространяются по SIL OFL; тексты лицензий сохранены в `assets/fonts`.

## Открытые примеры, изученные при работе

- [Brittany Chiang / v4](https://github.com/bchiang7/v4), в частности [раздел проектов](https://github.com/bchiang7/v4/blob/main/src/components/sections/projects.js): короткая подборка до раскрытия всего архива, ясная иерархия карточек, реакции на hover/focus и уважение к reduced motion. Эти общие принципы адаптированы к галерее рендеров.
- [Bruno Simon / Folio 2019](https://github.com/brunosimon/folio-2019), в частности [Areas](https://github.com/brunosimon/folio-2019/blob/master/src/javascript/World/Areas.js) и [Application](https://github.com/brunosimon/folio-2019/blob/master/src/javascript/Application.js): характер портфолио через взаимодействие и поддержка touch наряду с мышью. Здесь это выражено через объёмную композицию, реакции карточек, просмотр и свайпы; постоянный WebGL-рендеринг для этого проекта не требуется.

Реализация HTML, CSS и JavaScript написана для CriSpy. Код, личный контент и графические материалы этих портфолио не переносились. Изображения — существующие работы владельца репозитория. Отзывы, контакты, сроки и исходный прайс сохранены по содержанию.

## Производительность

- Оригиналы оставлены для просмотра и скачивания; карточки используют WebP с `srcset` и `sizes`.
- 48 превью занимают около 1,56 MiB в сумме. `render12-960.webp` занимает 34 724 байта, оригинал — 5 380 938 байт.
- Изображение первого экрана получает `fetchpriority="high"`. Остальные загружаются лениво; дополнительные карточки скрыты до раскрытия подборки или фильтрации.
- Размеры изображений и пропорции контейнеров заданы заранее.
- Нет CDN, внешних иконок, Google Fonts API, аналитики или клиентского фреймворка.
- JavaScript загружается с `defer`. Для прокрутки используется один пассивный обработчик с `requestAnimationFrame`; постоянного animation loop нет.

В локальном сравнении с исходной версией при viewport 1440×1000 и новом контексте Chromium для каждой страницы первоначальные локальные HTTP-ответы составили 20 907 826 → 494 373 байт (−97,6%). Считались тела успешных ответов до networkidle, без HTTP-сжатия; внешние запросы блокировались в обеих версиях. Это объём загрузки в одном воспроизводимом сценарии, а не замер полной галереи после раскрытия или обещание конкретного балла PageSpeed. Подробности — `docs/performance.json`.

## Доступность и отказоустойчивость

Семантические разделы, один h1, skip link, видимый фокус, подписанные кнопки, статусы поиска, `aria-pressed`, `aria-expanded`, нативный modal dialog с удержанием и возвратом фокуса. При reduced motion отключены анимации, наклон первого экрана и плавная прокрутка. При отключённом JS доступны все изображения и контактные ссылки. Ошибка localStorage или Clipboard API не блокирует страницу.

Сайт не сохраняет текст заказа. Избранное хранится только в браузере посетителя и не синхронизируется с сервером. Отдельный backend не нужен.
